# Codex Task: Phase 6 — Travel v2 event outcome package and GM-reviewed session apply

## Repository

`p1ng3r/arcflight`

## Base branch

`codex/phase-6-event-outcome-package-and-gm-apply`

## Context

Phase 5 is complete. The Travel v2 runner can now:

1. preview pressure from station outcomes.
2. apply pressure to the session.
3. correct pressure applications.
4. finalize rounds.
5. show event completion readiness.
6. complete the Travel v2 runner session locally.

Phase 6 should move forward at a larger, useful pace.

This task should create the event outcome package and let the GM apply that package to the completed runner session state.

Do not mutate PF2E actors/items yet. Actor/item mutation will be a later explicit GM-approved bridge. This PR should still be useful: the completed session should now contain a stable, reviewed outcome package and an applied session-local outcome record.

## Goal

After a Travel v2 event is completed, generate a deterministic event outcome package from the completed session, show it to the GM, and allow the GM to apply/lock that outcome package into the runner session.

The package should summarize:

- event result summary.
- round outcomes.
- pressure deltas applied during the event.
- hazard/scar candidates already generated by pressure systems.
- possible fortune/reward candidates if existing data supports them.
- consequence candidates if existing data supports them.
- GM-facing next-step text.

The apply action should mark the outcome package as accepted/applied to the runner session only.

### Event outcome key

Determine a simple summary key from finalized round records:

- `critical-success` if most/all rounds are critical-success where that data exists.
- `success` if success-like outcomes exceed failure-like outcomes.
- `mixed` if outcomes are mixed or unclear.
- `failure` if failure-like outcomes exceed success-like outcomes.
- `critical-failure` if most/all rounds are critical-failure where that data exists.

Use conservative fallback:

```text
mixed
```

Support common outcome fields:

```js
effectiveOutcomeKey
outcomeKey
selectedOutcomeKey
```

## New helper: session-local outcome application

Add:

- `scripts/helpers/travel-v2-session-event-outcome-application.js`

Exports:

```js
export const TRAVEL_V2_SESSION_EVENT_OUTCOME_APPLICATION_VERSION = 1;
export function applyTravelV2EventOutcomePackageToRunnerSession(session, options = {}) { ... }
```

Rules:

- Uses `prepareTravelV2EventOutcomePackage(session, options)`.
- Blocks if package cannot be prepared.
- Blocks if package already applied.
- Clones session on success.
- Writes session-local outcome application record only.
- Does not mutate actors/items/chat/socket/player cards.
- Does not apply real scars/fortune/rewards to actors/items yet.

Recommended session field:

```js

  applied: true,

  helperVersion,

  pressureSummary,
  hazardSummary,
  shipScarCandidates,
```

## Safety boundaries

This PR may update the runner session only.

Do not mutate PF2E actors.
Do not mutate PF2E items.
Do not emit sockets.
Do not send chat.
Do not touch player station cards.
Do not apply scars to actors/items.
Do not award actual fortune to actors/items.
Do not apply actual rewards/consequences to actors/items.
Do not roll random rewards.
Do not change pressure math.
Do not change Hard Correction logic.
Do not auto-apply during render/state preparation.
Do not expose application controls to players.
